# feat!: every Toolkit 1.0 resource on the /api/v2 shapes

Primary record: alva-gateway
`docs/changelogs/2026-11-19-agent-api-permissions.md`, Appendix S (D17, D29,
D30, D31, D46, D49, 10.7, A11). Core: `2026-11-20-toolkit-1.0-v2-core.md`.
This change moves the resources onto that core in three slices (market,
billing, runtime and trading; content; account, files, automation and
social) and integrates them. It supersedes the mapping-layer resource
changelogs of 2026-11-19 (`agent-api-v2-market-trading-runtime`,
`content-resources-v2`, `agent-api-v2-social-automation-files-account`).

## 1. Background and Current State

- After the core, the resources still mapped every `/api/v2` answer back to
  its 0.x shape through `Wire*` types, validators and mapping files
  (`thesisReads.ts`, `thesisPublication.ts`, `brokerAccounts.ts`, ...), and
  some fell back to `/api/v1` by credential (`_sendsApiKey`).
- `test/openapi-pending.txt` listed 7 call sites not yet on the contract
  (fs, schedules, theses star, x).

## 2. Behavior

- B1: every SDK method takes and returns the generated `Schema<'…'>` and
  `V2Query<…>` types of the route it calls; no `Wire*` type, validator or
  0.x mapper remains outside `client.v1`.
- B2: methods without an `/api/v2` route are on `client.v1` with their 0.x
  types: `steward`, `secrets.get`, `notifications.listFeed`,
  `subscriptions.subscribeFeed`/`unsubscribeFeed`,
  `channelGroupSubscriptions` (context, list, subscribe, unsubscribe), `fs`
  for PBSV, viewer and keyless public reads, `trading.subscribe` with
  `executeLatest`, and keyless `playbooks`/`playbookSkills` discovery.
- B3: every `_v2Request`, `_v2Fetch` and `_v2Pages` call site in `src/`
  names an operation of the vendored document; the pending list is gone.
- B4: the CLI's JSON output is the SDK result, and `--json` is accepted on
  every command of the terminal and embedded catalogs.
- ~~B5: `asks.create` returns the `AskOperation`; `asks.wait` polls after 1, 2
  and 4 s, then every 5 s, for at most 35 minutes; `alva ask` waits.~~
  Removed 2026-11-24 with the gateway route (section "2026-11-24" below).
- B6: `fs.read` returns raw bytes (`{data, contentType, contentRange}`);
  `fs.write` takes bytes or a string.
- B7: orders are placed with
  `trading.placeOrders(accountId, instruction, {idempotencyKey})`; every
  account flag takes the BrokerAccount ID; `alva broker --account-id`
  becomes the invocation's `accountId`.
- B8: `getByIds([])` is `[]` without a request; `get`-style reads return
  `null` only on 404; `theses.related` throws reason
  `RELATED_THESES_GENERATING`; For You items carry `version` and `thesis`
  apart.

## 3. Decisions to review

From the slices (each recorded with the slice's commit):

- Market, billing, runtime, trading:
  - `alva run` prints the `Run` with `returnValue` decoded from its JSON
    text (the 2026-10-08 output decision); the one CLI JSON output that is
    not the SDK result unchanged.
  - The CLI sends `--working-dir` only with `--code` (the route refuses
    `workingDir` with `entryPath`).
  - `trading execute --signal` is replaced by `--instruction` (an
    `OrderInstruction`) and `--idempotency-key`; `--signal`,
    `--source-username` and `--source-feed` are errors naming the
    replacement (also embedded `trading signals execute`).
  - Embedded `trading accounts` and `trading risk-rules` read `/api/v2`
    instead of the broker, which the gateway refuses for `accounts`.
  - `trading.accounts` and `trading.portfolio` are folded into
    `portfolio.accounts` and `portfolio.snapshot`; `alva trading accounts`
    asks for every mode except `READ_ONLY`.
  - Renames to the route resources: `portfolio.summary` → `snapshot`,
    `trading.equityHistory` → `equity`, `credits.items` → `entries`,
    `markets.earningsPeriods` → `earningsCalendar`.
  - Markets methods take the Asset ID; the ticker lookup and `--event`
    selection are in the CLI; local not-found errors are `NOT_FOUND`.
  - `tradingPairs.search` and `resolve` stay as client-side exact matching
    over `GET /trading-pairs` (no exchange or quote filter on the route).
  - `trading subscribe` requires `--signal-source-id`;
    `equity-history` refuses `--timeframe`, `--since-ms`, `--until-ms`.
  - Optional `{idempotencyKey}` on `run.execute`, `functions.invoke`,
    `trading.subscribe` and `unsubscribe` (Spends/Trades routes).
  - `functions delete` and `allowance revoke` print nothing.
  - `alva credits items --last` cannot be paged with `--after`: the window
    moves with the clock and page tokens are bound to the filters.
- Content:
  - CLI JSON flags take v2 member names: `--entity-stances`
    `[{assetId, stance}]` with an upper-case Stance, `--medias` the
    `MediaInput` of `currentVersion.media`, `--feeds`
    `[{automationId, major}]`; 0.x members are usage errors.
  - `thesis version get --id` is removed (`--author-version-id`, or
    `--number --version`); `thesis update` has no `unchanged` member,
    `--visibility` is optional and omitted members carry over (D49).
  - `theses.setArchived` → `archive`/`unarchive`;
    `playbooks.setVisibility({name, visibility})` → `update(id, patch)`;
    `comments.create`, `remix.save` and `release.playbook` take Playbook
    IDs. `playbooks set-visibility` still always sends
    `confirmBundledFeedExposure: true`, as v1 did.
  - `playbookSkills.list`/`tags` and `sdk.partitions` return one page; the
    CLI reads every page and prints `{items, nextPageToken: null}`.
  - Without an API key the CLI's playbooks and skillhub reads use
    `client.v1` and print the 0.x shapes.
  - SDK checks the gateway also enforces are removed; the CLI keeps the
    `--images` checks, the stance-to-asset check and enum flags.
    `feed.setVisibility` refuses anything but `PUBLIC` or `PRIVATE` (any
    other value would unpublish).
- Account, files, automation, social:
  - `schedules` is split into a Channel family and a Session family so each
    call names one literal route; the name lookup is in the CLI.
  - `follows.unfollowAssets`, `subscriptions.unsubscribeBatch` and
    `schedules.agentChannelId` make several v2 calls each.
  - `markets watchlist add|remove` refuses every ticker without an Asset
    with `NOT_FOUND` before writing (0.x returned a partial result).
  - `asks.wait` throws the failed operation's problem; after 35 minutes it
    throws `DEADLINE_EXCEEDED` (504).
  - `alert history --automation-id` reads `/me/notification-deliveries`;
    `--automation owner/name` and `notification-history list-feed` stay on
    `client.v1` (their RFC 3339 `--since` is sent as Unix seconds).
  - `deploy run-status --workflow-run-id` keeps its name and takes the
    `dispatchId`; new `deploy run-stats`.
  - `automation.delivery.update` returns the PATCH answer; `--channel-id 0`
    and `--alva-channel-ids 0` still mean the Agent channel.
  - `secrets delete --name` finds the Secret ID in the CLI.
  - `channelGroupSubscriptions` keeps only `getGroupChatHistory` on v2: the
    toolkit holds a numeric origin session, not the Session ID the
    `/sessions/{sessionId}/…` routes take.

From the integration:

- I1: one page reader, `src/cli/pages.ts` (a repeated page token is
  `INVALID_RESPONSE`, a server fault), replaces the content slice's copy
  (`CliUsageError`).
- I2: one RFC 3339 flag parser, `src/cli/timeFlags.ts`. The `--since` of
  `trading orders` now sends the normalized `toISOString()` form, with the
  shared "Unix timestamps are no longer accepted" error.
- I3: `automation.stop`, `resume` and `delete` take the Automation ID like
  `feed` and `inspect`; the last 0.x request types (`FeedDeleteRequest`,
  `FeedStatusUpdateRequest`) are gone.
- I4: the CLI resolves Playbook slugs and tickers through
  `playbooks.getBySlug` and `markets.assetBySymbol` (the slices called the
  transport directly while the other slice's method was missing). The
  broker passthrough keeps its direct `POST /broker/invocations` call: it
  has no SDK resource.
- I5: `_sendsApiKey` is removed (no caller); `test/openapi-pending.txt` is
  removed and the call-site test requires zero mismatches.
- I6: `--json` is a global boolean of both catalogs (contract 10.7,
  "`--json` everywhere"); the embedded catalog forwards it to the terminal
  command as a switch. On a command without a human format it changes
  nothing; `fs read` still prints the file.
- I7: the embedded automation composites print camelCase
  `{automationId, cronjobId, automation, producer}` with the v2 objects
  (the slice kept `automation_id`, `cronjob_id` and a lower-case
  `status`), closest to D17 for outputs that span several routes.
- I8: the README resource table lists every resource and `client.v1`.

## 2026-11-24: asks removed

- The program owner removed `POST /api/v2/asks` and
  `GET /api/v2/ask-operations/{askOperationId}` from the platform
  (https://github.com/alva-ai/alva-gateway/pull/1510). It started a one-shot
  turn through the backend's `StartChat`, which takes no request id: a
  same-key retry after a lost call could start a second paid turn. Both were
  new in 1.0, so 1.0 ships without them.
- Removed `src/resources/asks.ts` and its test, `client.asks`, the
  `AsksResource` export, `alva ask` (definition, help, dispatch) and its CLI
  tests; README and CHANGELOG no longer mention asks.
- `npm run openapi:sync` from alva-gateway#1510's `openapi.json`
  (gateway `main` after #1505 and #1506, minus asks), then
  `npm run openapi:gen`: the contract also gains
  `POST /admin/thesis-backfills` and `NewVisibility`.
- Verification: `npm run typecheck`, `npm run lint`: clean;
  `npx vitest run`: 76 files, 1261 tests passed.

## 2026-11-26: screenshots removed

- The screenshot endpoint is retired on both API versions, so 1.0 ships
  without `client.screenshot` (on `POST /screenshots`), `alva screenshot` and
  the embedded `playbooks screenshot`. The same removal on `main` is
  `docs/changelogs/2026-11-26-remove-screenshot-command.md`.
- Removed `src/resources/screenshot.ts` and its test, `client.screenshot`,
  the command (definition, help, dispatch), the embedded action (138 leaves),
  and what only screenshots used: `src/base64.ts` and its test, the CLI's
  `_image` output, `writeLocalFileBytes` and `DispatchLocalFiles.writeBytes`,
  the `aScreenshot` fixture. README and CHANGELOG follow.
- The vendored contract still lists `POST /screenshots` until the next
  `npm run openapi:sync` from the platform contract that drops it, then
  `npm run openapi:gen`; no call site uses it.
- Verification: `npm run typecheck`, `npm run lint`, `npm run format:check`:
  clean; `npm test`: 74 files, 1273 tests passed.
