# feat: the /api/v2 transport for Toolkit 1.0

Primary record: alva-gateway/docs/changelogs/2026-11-19-agent-api-permissions.md
(D10 conventions, D16 IDs, R16, 4.2 and 4.6 M20). Rule text:
alva-gateway/doc/api-v2-conventions.md.

## 1. Background and Current State

- Toolkit 0.36.0 calls `/api/v1` REST routes and GraphQL through
  `AlvaClient._request`, which reads the v1 error envelope
  `{"error": {"code", "message"}, "details"}` and never retries (steward's
  pending read is the one bounded, immediate retry).
- The gateway now serves `/api/v2` (P2, one domain at a time): camelCase JSON,
  `{items, nextPageToken}` lists with `pageSize` and `pageToken`, repeated
  query parameters for lists, JSON Merge Patch on PATCH, RFC 9457 problems
  with `code`, `requiredPermission`, `invalidParams` and `retryAfter`, an
  `Idempotency-Key` that routes mirroring an `idempotencyKey` mutation
  require, and D16 IDs (`task_0…`) that clients treat as opaque strings.
- The gateway's authentication middleware still writes the v1 envelope on
  `/api/v2` (invalid API key, banned account) before a route's problem
  writer runs.
- M20 moves every Toolkit resource to `/api/v2` in a 1.0.0 major release
  whose breaking change is the ID format (human decision); public method
  signatures and output otherwise stay as they are (R16).

## 2. Behavior

- B1: `client._v2Request(method, path, options)` sends to
  `{baseUrl}/api/v2{path}` with the credential, analytics and origin-session
  headers `_request` sends, and the same timeout, abort and network-error
  handling.
- B2: query parameters skip `undefined` and `null` and repeat a parameter per
  array element (`?status=A&status=B`).
- B3: a JSON body is `application/json`; on PATCH it is
  `application/merge-patch+json`, and `null` members are sent (they clear).
- B4: every non-GET request carries an `Idempotency-Key`: the caller's key,
  unchanged on every attempt of one logical write, or a new UUID per call.
- B5: a failed response becomes an `AlvaError`: from a problem, `code`,
  `status`, `message` (detail, else title) and, when present,
  `requiredPermission`, `invalidParams` and `retryAfter` (the problem's, else
  the `Retry-After` delta-seconds); from the v1 envelope, as `_request` reads
  it; from any other body, `UNKNOWN` with the status and body text. Errors
  without these members do not gain the properties.
- B6: `client._v2Pages(path, options)` yields pages, sending `pageSize`, the
  list's other parameters and the previous `nextPageToken`, until the token is
  null or empty; `collectAll` returns their items in order. A response that is
  not a page, or that repeats the token it was sent, is `INVALID_RESPONSE`.
- B7: `v2Path` percent-encodes each interpolated value as one segment and
  refuses an empty, `.` or `..` value.
- B8: the CLI's error JSON adds `requiredPermission`, `invalidParams` and
  `retryAfter` when the error has them; other errors print as before.
- F1: `_request` and every resource behave as before; no resource moves here.

## 3. Decision

- D1: one transport method beside `_request`, sharing its header and fetch
  code (`_headers`, `_send`, `decodeResponse`), so both doors keep one
  credential, timeout and network-error path.
- D2: no new automatic retries (the record: Toolkit does not retry). The
  Idempotency-Key makes the retries that exist safe: a resource method that
  takes a request ID passes it as `idempotencyKey`, and an agent retrying the
  same command reuses it. `retryAfter` is exposed for the one retrying caller
  (steward) to use when it moves.
- D3: the new `AlvaError` members are optional and assigned only when
  present (declared fields), keeping the shape of every other error and the
  CLI output of v1 errors.
- D4: `details` stays undefined for a problem: its members are all mapped,
  and the problem carries no backend reason.
- D5: the v1 envelope is still read on `/api/v2`, because the gateway's
  authentication middleware writes it there.
- D6: `AlvaId` (`string`) is the public ID type. Each resource's ID fields
  switch to it when that resource moves to `/api/v2`, so no type claims a
  string while its route still returns a number.
- D7: `generateRequestId` moves from the steward resource to the transport
  module, its one shared UUID source.

## 4. Implementation

- `src/platformApi.ts`: `V2Method`, `Query`, `V2RequestOptions`, `Page`,
  `V2PageOptions`, `encodeQuery`, `v2Path`, `generateRequestId`,
  `v2ResponseError`, `collectAll`.
- `src/client.ts`: `_v2Request`, `_v2Pages`; `_request` split into
  `_headers`, `_send` and `decodeResponse` without a behavior change.
- `src/error.ts`: `InvalidParam`, `ProblemFields`, the three `AlvaError`
  members, `alvaErrorOutput` (the CLI's error JSON).
- `src/types.ts`, `src/index.ts`: `AlvaId`; exports `InvalidParam`,
  `ProblemFields`, `Page`.
- `src/cli/index.ts`: prints `alvaErrorOutput`.
- `src/resources/steward.ts`: imports `generateRequestId`.
- `README.md` (Migrating from 0.x to 1.0, Error Handling), `CHANGELOG.md`
  (new; 1.0.0 skeleton, completed as resources move).

## 5. Verification

- `test/platformApi.test.ts` (18 tests): query encoding, `v2Path`, request
  URL and headers, Merge Patch with null, 204, a new key per write, one key
  across two attempts, problem parsing (permission, invalid params,
  `retryAfter` precedence, title, v1 envelope, plain text, no new
  properties), CLI error JSON, pagination (token chain with other
  parameters, start token, early stop, not a page, repeated token), UUID v4
  without `crypto.randomUUID` (moved from the steward test).
- Mutations, each caught by a failing test and restored: `set` instead of
  `append` in query encoding; JSON instead of Merge Patch on PATCH; ignoring
  the caller's key; a fixed key; dropping `requiredPermission`; header before
  body for `retryAfter`; dropping `invalidParams`; dropping the list's other
  parameters; no repeated-token guard; allowing `.` and `..` segments; and
  defined (not declared) fields, which gave every error the new properties.
- `npm run lint`, `npm run format:check`, `npm run typecheck`, `npm test`
  (63 files, 1,480 tests), `npm run build`: pass (2026-11-19).

## 6. Human Decisions

- 2026-11-19 (primary record, section 6): `/api/v2` with camelCase and
  RFC 9457; D16 IDs with a clean switch and a Toolkit major version;
  Toolkit's public output unchanged apart from IDs.
- 2026-11-19: follow the recommended designs and record the uncertain points.

## 7. Deviations and open points

- `package.json` stays at 0.36.0: `scripts/release.sh major` bumps it to
  1.0.0 at release, and a pre-bumped 1.0.0 would release as 2.0.0
  (`2026-11-16-thesis-watchpoints.md` took the same course).
- The repository had no `CHANGELOG.md`; this change creates it for the 1.0
  notes (record 4.8).
- Browser and PBSV callers: `/api/v2` sends no CORS allowance and treats a
  PBSV as a guest, so resources the browser bundle or Playbook runtime use
  need a decision when they move.
