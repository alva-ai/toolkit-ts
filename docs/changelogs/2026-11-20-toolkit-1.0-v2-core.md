# feat!: Toolkit 1.0 core on the /api/v2 contract

Primary record: alva-gateway
`docs/changelogs/2026-11-19-agent-api-permissions.md`, Appendix S (the SOTA
revision: D17, D18, D23, D24, D46, 5.1, 10.7). This change is the core the
resources build on; each resource's move is recorded with it.

## 1. Background and Current State

- Toolkit's 1.0 branch called `/api/v2` through `_v2Request` and mapped every
  answer back to its 0.x shape through hand-written `Wire*` types and
  validators. D17 replaces that: the SDK returns the `/api/v2` shapes, typed
  from the gateway's OpenAPI 3.1 document (`pkg/v2/api/openapi/openapi.json`,
  served at `GET /api/v2/openapi.json`).
- The transport sent a bare UUID `Idempotency-Key` on every non-GET request
  and never retried (transport changelog D2); problems were read without
  `reason`; `_request` had its own v1 error parser; the build produced a 1.x
  browser bundle that unversioned unpkg URLs would pick up.

## 2. Behavior

- B1: `openapi/alva-platform-v2.json` is the gateway's document, byte for
  byte (`npm run openapi:sync -- <path-or-url>`); `src/generated/platform-v2.ts`
  is generated from it (`npm run openapi:gen`, openapi-typescript 7) and
  `test/openapi.test.ts` fails when it is stale.
- B2: every `_v2Request`, `_v2Fetch` and `_v2Pages` call site in `src/` names
  a literal method and path template (string, `v2Path` template, or each
  branch of a conditional) that the document declares; `_v2Request` and
  `_v2Pages` only on routes that answer JSON. Sites not yet on the contract
  are listed in `test/openapi-pending.txt`, which must match exactly.
- B3: POST and PATCH carry one `Idempotency-Key` per call, quoted
  (`"<uuid>"`); a caller's key is quoted, and one the gateway would refuse
  is `INVALID_ARGUMENT` reason `IDEMPOTENCY_KEY_INVALID` before sending. GET
  and DELETE carry none.
- B4: a network error, 409 `IDEMPOTENCY_KEY_IN_USE`, 429 with `Retry-After`
  ≤ 30 s, 502, 503 and 504 (not `RELATED_THESES_GENERATING`) are retried with
  the same key and body bytes: at most 3 attempts, within 60 s, waiting
  max(`Retry-After`, 0.5 s × 2^(n-1) ±20 %). An abort during the wait ends
  the call with `NETWORK_ABORTED`.
- B5: a client holding a PBSV or viewer token is refused by every `/api/v2`
  call with `CREDENTIAL_REQUIRED` (401) before sending.
- B6: `_v2Request` returns a JSON object or throws `INVALID_RESPONSE` (502);
  `_v2Fetch` returns the successful `Response` (raw bytes, headers).
- B7: `AlvaError` has `reason` and `type`; one parser (`responseError`) reads
  `/api/v2` problems, the v1 envelope and other bodies for both transports;
  the CLI's error JSON adds them.
- B8: no test reaches a network: `test/setup/no-network.ts` replaces `fetch`
  and undici's global dispatcher with refusing stubs.
- B9: `dist/browser.global.js` is the published 0.36.0 bundle
  (`legacy/browser-0.36.global.js`); there is no 1.x browser entry.
- B10: `client.v1` (`V1Resources`) holds the 0.x methods without an
  `/api/v2` route; resources move into it.

## 3. Decisions to review

- D1 (deviation from 10.7): the types are generated without
  `--path-params-as-types`. With it, openapi-typescript 7.13 emits template
  literal index signatures that overlap (`/assets/${string}` and
  `/assets/${string}/candles`), which `tsc` refuses (TS2413) in a `.ts`
  source. The default keys `paths` by the document's templates, which also
  lets `V2Query<'/me/credit-entries', 'get'>` name a route's query type.
- D2: the generator is the programmatic API (`scripts/openapi.ts`), which
  both `openapi:gen` and the test call, so the comparison cannot drift from
  the script; its output equals the CLI's.
- D3: `_v2Fetch` is the transport, `_v2Request` its JSON form. `fs/read` and
  `openapi.json` answer raw bytes (`*/*`), which the object rule would
  refuse; the call-site test routes them to `_v2Fetch`.
- D4: the retry wait applies the jitter to the backoff, not to
  `Retry-After`: max(`Retry-After`, backoff ± 20 %), so a retry never comes
  before the server's time. A timed-out attempt (`timeoutMs`, per attempt)
  is not retried: the caller's deadline holds.
- D5: no credential is not refused on `/api/v2` (`GET /openapi.json` is
  anonymous); the gateway answers 401.
- D6: `generateRequestId` keeps its fallback (`crypto.randomUUID`, else
  `getRandomValues`, else `Math.random`): the client is also bundled for the
  embedded Dispatch (platform browser), so it imports no `node:crypto`, and
  Node 18 has no global `crypto` by default.
- D7: the call-site ratchet (`test/openapi-pending.txt`) lets the resources
  move one at a time; it lists 7 sites (fs, schedules, theses star, x) and
  goes when empty.
- D8: the frozen bundle is 0.36.0 as the record decides, although 0.37.0
  was published on 2026-11-20 and unversioned unpkg URLs serve it today; it
  differs from 0.36.0 only by the removed `theses.restore`. Its
  `sourceMappingURL` names a map 1.x does not ship (a DevTools warning).
- D9: `orNull` (null on 404 only) is in `platformApi.ts` for the resources.

## 5. Verification

- Tests: `test/openapi.test.ts` (regeneration, call-site reader, every call
  site), `test/platformApi.test.ts` (keys, retries, credentials, object
  rule, raw route, problems, v1 parser, CLI error JSON, `orNull`),
  `test/noNetwork.test.ts`, `test/legacyBrowser.test.ts`,
  `test/client.test.ts` (`v1`).
- Mutations, each caught by a failing test and restored: unquoted key; a key
  on DELETE; retrying 500; retrying `RELATED_THESES_GENERATING`; no 60 s
  budget; four attempts; no PBSV refusal; accepting a non-object; jitter on
  `Retry-After`; dropping `reason`; `_request` with its own parser; `orNull`
  on 403; accepting any key; a stale generated file; a call site to an
  undeclared route; no conditional paths in the reader; no setup file; one
  byte appended to the frozen bundle.
- Resource tests that changed with the transport: quoted keys, DELETE fakes
  answering `{}` (the document's shape), the Related fake carrying
  `RELATED_THESES_GENERATING`, a 500 instead of a 503 for "not retried".
